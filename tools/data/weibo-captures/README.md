# 微博增量收录

`2026-11-13.json` 是登录后的移动端网页 DOM 采集：2144jx（6306512172）的「微博」时间线，逐条打开全文、图片查看器，回溯到已有的 2026-10-11 存档。置顶旧帖不重复收入。新增 6 条原创微博、23 张图片（含 1 张视频封面），没有新增头条文章。11 月 5 日的转发帖 `5361956267495437` 沿用原创限定范围，记入 excluded。

每条保留原始 HTML、DOM 上计算的 FNV-1a 校验值、显示时间、图片顺序、原帖链接及采集时的互动数。显示时区为日本时间；用旧帖在页面显示的 16:32 与旧存档的 15:32:48 交叉核对，归档统一换算为北京时间。页面只显示到分钟，因此新记录明确标记 `date_precision: minute`，`:00` 是格式占位。原帖用词、错别字、段落及表情代码保留；评论区不混入正文。

`2026-11-13-media.json` 记录观察到的图片 URL、源文件和 CDN 副本的尺寸、大小、SHA-256。保存的是图片查看器提供的 mw2000 图片与 orj480 视频封面，不宣称是相机原始分辨率。沿用站点现有策略，转存 JPEG 最长边 1600px，质量 82；视频保留封面和原链接，没有保存视频文件。所有 23 个对象上传至现有 COS 的 `weibo-notes/` 前缀。

采集文件不含登录凭据，放在不发布的 tools 目录中。原始图片与完整历史数据仍保存在本地 `P:/weibo`。

导入顺序：

1. 备份本地 `_work/dataset.json`；验证新捕获的全文、时区、原创范围和图片顺序。
2. 按 `image_urls` 保存到 `P:/weibo/img_new/`，生成 `_work/cos/` 下同名图片并上传现有媒体存储；核验 CDN 内容。
3. 先预览，再加 `--apply`：`python tools/import-weibo-capture.py tools/data/weibo-captures/2026-11-13.json`。可用 `--dataset` 指定其他历史数据副本。
4. `python tools/build-weibo-notes.py` 仅更新碎片页和首页封面索引。没有新长文时不要运行全量长文生成器，避免覆盖手工修订。
5. 对比旧记录、旧卡片及长文，渲染检查，然后走分支检查与发布流程。

导入器按 MID 去重，重复导入不会更新旧正文或互动数。已有 MID 的正文、图片或日期变化会中止，须另行复核修订。未确认全文、源 HTML 校验失败、缺图、冲突、转发混入等情况也会中止。不要用旧的全量 `build_dataset.py` 覆盖这些增量记录；后续采集应继续使用增量导入。

验证：`python -m unittest discover -s tools/tests -p test_weibo_capture.py`。

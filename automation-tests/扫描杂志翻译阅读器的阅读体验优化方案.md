# 扫描杂志翻译阅读器的阅读体验优化方案

> 文档定位：产品与界面设计方案，可直接用于设计评审、前端拆分和迭代排期  
> 适用范围：包含杂志扫描页、OCR 原文、翻译、Region、Entity、校对与注释信息的桌面端阅读器  
> 核心目标：保留现有资料研究能力，同时将默认体验从“查看结构化资料”转变为“自然地读完一篇文章”

---

## 1. 背景与目标

当前页面的信息完整度很高：用户可以同时看到扫描原刊、选区、日文原文、中文翻译、人物或作品标签、OCR 与校对说明。这套界面适合核对和研究，但不适合作为默认阅读入口。

问题并非单纯的“信息太多”，而是所有信息几乎拥有同等视觉权重。用户需要不断在扫描图、Region、原文、翻译和说明之间切换，阅读过程因此变成逐项处理资料。

本次优化的目标是：

1. 让普通读者能够连续、低干扰地读完内容；
2. 让原文、原刊、OCR、实体和校对信息在需要时随时可达；
3. 保留现有 Region 数据及研究能力，避免推翻后台结构；
4. 用清晰的模式分工，降低一个页面同时承担所有任务造成的复杂度。

### 1.1 成功体验的判断标准

- 进入页面后，用户第一眼看到的是标题和正文，而不是控制面板；
- 默认状态下，视线可以从文章开头连续移动到结尾；
- 查看一句原文或对应原刊位置不需要离开当前阅读进度；
- Entity、OCR、Region ID 等技术信息不会主动打断普通阅读；
- 专业用户仍能在研究模式中获得现有页面的完整信息密度。

## 2. 现状问题诊断

### 2.1 信息主次不清

当前界面中，以下元素同时争夺注意力：

- 大幅扫描原刊；
- 多个 Region 内容卡片；
- 日文与中文并排文本；
- 人物、作品、宝可梦等 Entity 标签；
- OCR、校对、注释和数据状态；
- 阅读模式切换、区域导航与页面缩放控制。

这些元素本身都有价值，但没有按照阅读任务建立层级。结果是正文没有成为页面的视觉主角，用户需要先理解界面，再开始理解文章。

### 2.2 Region 被直接卡片化

Region 是合理且必要的数据结构，可用于坐标映射、OCR 管理、翻译对齐、检索和校对。但当前展示将每个 Region 直接转译成一张独立卡片：

```text
Region 1
原文｜翻译｜说明
──────────────
Region 2
原文｜翻译｜说明
──────────────
Region 3
原文｜翻译｜说明
```

这种设计让用户感受到的是“逐条处理数据”，而不是“阅读一篇文章”。段落间的边框、留白和重复元信息进一步切断了文章的语义连续性。

需要明确：

> Region 是内容的底层索引单位，不应默认成为前台的视觉容器。

### 2.3 双栏对照持续打断阅读

固定的“日文｜中文”双栏适合逐句核对，但会让阅读者反复横向移动视线、寻找对应关系，并在两种语言之间切换认知上下文。对于采访、叙事和长段正文，这种成本会快速累积。

双栏对照不应消失，但应从默认阅读形态调整为一个明确的核对模式。

### 2.4 标签与 OCR 校对形成“数据库感”

Entity 标签、OCR 置信度、校对状态、Region 编号等信息在数据管理与研究场景中非常有用，但它们会向普通用户暴露内容生产管线。大量徽标、边框、状态色和字段名使页面更像档案系统或管理后台。

这类信息应遵循“按需出现”的原则，而不是与正文长期共存。

### 2.5 原刊占据过高注意力

原刊扫描页通常具有强烈的图片、字体和版式表现力。当它固定占据约一半屏幕时，视线会自然被原刊吸走。用户即使在阅读翻译，也会不断受到左侧视觉刺激。

原刊在阅读模式中应作为上下文和证据存在，而不是与译文争夺主导地位。

## 3. 核心设计原则

### 3.1 默认状态只负责“让用户读下去”

默认界面只保留对理解和继续阅读直接必要的信息：

- 标题、副标题与必要的文章背景；
- 主语言正文；
- 克制的文章级导航；
- 低存在感的原刊入口和语言入口。

其他能力不删除，而是降低到第二层或专门模式。

### 3.2 Progressive Disclosure（渐进式披露）

信息按照用户意图逐层出现：

| 层级 | 默认可见内容 | 触发方式 | 典型用途 |
|---|---|---|---|
| 第一层 | 标题、主语言正文、阅读进度 | 无需操作 | 连续阅读 |
| 第二层 | 辅助语言、原刊缩略图、脚注 | 悬停、点击或快捷键 | 临时确认 |
| 第三层 | 对照视图、原刊选区、注释 | 切换模式 | 翻译核对 |
| 第四层 | Region、Entity、OCR、校对状态 | 进入研究模式 | 编辑与研究 |

渐进式披露的重点不是简单隐藏功能，而是让信息出现的时机与用户当下任务一致。

### 3.3 数据结构与视觉结构解耦

后台继续维护：

```text
Page → Region → Segment → Source / Translation / Entity / OCR metadata
```

阅读模式则根据语义顺序，将这些数据合成为：

```text
Article → Heading → Lead → Paragraph → Interview turn → Caption / Note
```

每一个正文节点仍可保存 `regionId`、原刊坐标与原文映射，但默认不显示其技术边界。

### 3.4 模式服务于任务，而不是服务于字段

用户想做的是阅读、对照、看原刊或研究，并不是“打开某一组字段”。一级模式应直接对应这四种意图。

## 4. 模式重构

一级模式建议重构为：

```text
[ 阅读 ]  [ 对照 ]  [ 原刊 ]  [ 研究 ]                      [ Aa ] [ ··· ]
```

### 4.1 阅读模式（默认）

目标：沉浸、连续地阅读文章。

- 仅展示主语言形成的连续内容流；
- 不展示 Region 卡片边界；
- 原刊以缩略入口或侧边浮层出现；
- 辅助语言按段或按句临时展开；
- 默认隐藏 Entity、OCR、校对与技术状态。

### 4.2 对照模式

目标：比较原文与译文，确认翻译关系。

- 可使用段落级双栏，而非碎片化 Region 卡片；
- 左右栏保持稳定对应和同步高亮；
- 使用柔和段间分隔，不重复展示无关元信息；
- 点击段落可定位原刊，但原刊不必固定占据半屏；
- 可提供“按段对照 / 逐句对照”二级选项。

### 4.3 原刊模式

目标：欣赏或查看杂志原始版面。

- 原刊扫描页是视觉主角；
- 支持缩放、翻页和全屏；
- 可选显示轻量选区轮廓；
- 点击选区时，仅浮出对应译文摘要；
- 默认不堆叠所有 OCR 和数据库字段。

### 4.4 研究模式

目标：编辑、校对、资料查询与结构化研究。

- 承接当前高信息密度页面；
- 展示原刊、Region、原文、译文、Entity、OCR 与校对信息；
- 保留区域导航、坐标选区、状态筛选等专业能力；
- 可以使用卡片、表格、标签和状态色，因为这些组件与研究任务一致。

### 4.5 原有模式的归并关系

| 当前入口 | 重构后的归属 |
|---|---|
| 阅读版 / 只看中文 | 阅读模式，中文设为主语言 |
| 只看日文 | 阅读模式，日本语设为主语言 |
| 日中对照 | 对照模式 |
| 原刊 + 选区 | 原刊模式；完整数据版本放入研究模式 |
| OCR / 校对 / Entity 开关 | 研究模式工具栏或“更多显示选项” |

## 5. 阅读模式：连续内容流

阅读模式不按照 Region 输出卡片，而应按照文章语义恢复内容结构。

### 5.1 推荐内容结构

```text
文章眉题 / 栏目名

文章标题
副标题或导语

采访者：问题……

受访者：回答……

后续正文段落……

图片说明 / 译注
```

不同 Region 之间若属于同一段或同一轮对话，应在渲染前合并。只有真实的语义变化，例如标题、换段、说话人变化、引用或图片说明，才创建视觉间隔。

### 5.2 内容组合规则

建议在展示层增加 `contentRole` 或等价映射：

```yaml
- regionId: r-003
  contentRole: headline
- regionId: r-004
  contentRole: lead
- regionId: r-005
  contentRole: interview-question
  speaker: interviewer
- regionId: r-006
  contentRole: interview-answer
  speaker: interviewee
```

若暂时无法修改数据模型，可在前端配置一层展示映射，先实现 Region 的合并、排序和角色样式。Region ID 继续留在 DOM 属性或内部状态中，用于定位与联动。

### 5.3 交互原则

- 正文选择或点击时才出现轻量操作菜单，如“查看原文”“定位原刊”“查看注释”；
- 展开辅助内容时，不应导致大幅跳动或丢失阅读位置；
- 从原刊浮层返回后，焦点回到原段落；
- 记住用户的主语言、字号和辅助语言偏好；
- 模式切换时尽量保持当前段落锚点。

---

## 6. 原刊的缩略入口与侧边浮层

阅读模式中，原刊建议采用两级呈现。

### 6.1 一级：低存在感入口

可在正文右侧或文章元信息区显示：

```text
[ 原刊 P.114 ↗ ]
```

或使用一张小尺寸、低对比度缩略图。入口应可发现，但不能比正文标题更醒目。

### 6.2 二级：侧边浮层

点击入口或段落的“定位原刊”后，从右侧展开浮层：

- 宽度约为视口的 32%–42%，正文无需完全退出；
- 自动定位当前段落对应的原刊页与选区；
- 当前 Region 轮廓高亮，其他选区默认隐藏或弱化；
- 支持缩放、拖拽和前后页；
- 关闭后保留正文滚动位置；
- 桌面大屏可固定浮层，小屏则使用全屏覆盖。

侧边浮层承担“随时核验”的职责，原刊模式则承担“完整浏览原版”的职责，两者不冲突。

## 7. 主语言与辅助语言策略

### 7.1 主语言优先

阅读模式一次只让一种语言承担正文角色。主语言由用户设置决定：

```text
语言
● 中文
○ 日本語

辅助语言
□ 点击段落时显示
□ 悬停时预览
```

中文读者默认以中文作为主语言；需要读原文的用户可切换日文。不要将“只看中文”和“只看日文”保留为多个同级产品模式，它们只是阅读模式的语言设置。

### 7.2 辅助语言的呈现方式

推荐优先采用“段落下方展开”：

```text
这次拍摄感觉如何？                         [原文]

撮影はいかがでしたか？
```

辅助语言样式建议：

- 字号为主语言的 85%–90%；
- 使用较低对比度文字；
- 与主文之间保持 6–10 px 间距；
- 不使用有色卡片和厚边框；
- 再次点击即可收起。

悬停预览可以作为桌面增强功能，但不能成为唯一入口，以兼容触屏和键盘操作。

### 7.3 Ruby 与注音

- 日文作为主语言时，可允许显示或隐藏 Ruby；
- 日文作为辅助语言时，Ruby 默认保持克制，避免行高不稳定；
- Ruby 属于语言显示设置，而不是文章级主操作。

## 8. Entity、OCR 与 Region 信息的处理

### 8.1 默认隐藏

阅读模式默认不展示：

- `Region 1 / Region 2` 等编号；
- 坐标、选区 ID 与数据状态；
- OCR 置信度、识别来源和校对记录；
- 人物、作品、宝可梦等 Entity 徽标；
- 翻译工作流与审核状态。

### 8.2 保留语义价值，隐藏技术形态

“隐藏 Entity”不等于删除知识入口。可将有明确阅读价值的实体处理为低干扰的正文链接：

```text
苍井优
```

点击后显示简洁人物卡，而不是在每个 Region 顶部反复显示标签。只有在研究模式中，才展示实体类型、ID、关联条目等完整数据。

### 8.3 信息出现的位置

| 信息 | 阅读模式 | 对照模式 | 原刊模式 | 研究模式 |
|---|---|---|---|---|
| Region 边界 / ID | 隐藏 | 默认隐藏，可选 | 仅选区映射 | 完整显示 |
| Entity | 正文链接或隐藏 | 可选 | 隐藏 | 完整显示 |
| OCR 信息 | 隐藏 | 可选异常提示 | 隐藏 | 完整显示 |
| 校对记录 | 隐藏 | 可选 | 隐藏 | 完整显示 |
| 原文 | 按需展开 | 主体内容 | 选区浮出 | 完整显示 |

## 9. 采访与正文排版建议

### 9.1 采访内容

采访应首先表现“谁在说话”和“对话节奏”，而不是表现数据块。

推荐样式：

```text
——这次拍摄感觉如何？

苍井优　现场有很多皮卡丘呢（笑）。让我有了一次很宝贵的体验。
```

具体建议：

- 采访者提问可使用破折号或较轻字重，不需要单独卡片；
- 受访者姓名使用半粗体，正文保持常规字重；
- 同一说话人的连续回答合并为自然段；
- 对话轮次间距大于段内行距，但小于章节间距；
- 长回答按语义分段，不按 OCR 框拆分；
- 不用不同背景色区分每位说话人，以免形成聊天应用或 Dashboard 观感。

### 9.2 普通正文

- 标题、导语、正文、引用、图片说明应建立稳定层级；
- 正文采用自然段，不对每段加边框；
- 段间距建议为 `0.75em–1em`；
- 小标题上方留白明显大于下方留白；
- 注释以脚注标记或段末展开呈现，不长期占据旁栏；
- 图片说明可以更小、更浅，但须保持可读性。

### 9.3 标点与文本规范

- 中文正文使用全角中文标点；
- 日文原文保留原刊或校对后的标点规则；
- 中日文切换不能破坏专名、数字和引用格式；
- OCR 产生的硬换行应在展示层合并；
- 原刊中的装饰性分行不应机械复制到连续正文中，除非它承载标题或诗歌等语义。

## 10. 视觉语言：去 Dashboard 化

当前页面的工具感主要来自卡片、徽标、分隔线、状态色和密集控件。阅读模式应建立更接近书刊的视觉语言。

### 10.1 应减少

- 每段独立白色卡片与阴影；
- 大量圆角胶囊标签；
- 贯穿内容区的分隔线；
- 高饱和状态色；
- 重复工具栏和始终可见的技术按钮；
- 网格化、等权重的模块布局。

### 10.2 应强化

- 纸张感但不过度拟物的中性背景；
- 由字级、行距和留白建立的信息层级；
- 稳定的纵向阅读轴；
- 克制的边缘控制和上下文操作；
- 清楚但安静的当前模式状态；
- 与原刊气质相容、适合长文阅读的字体组合。

### 10.3 建议视觉基线

```css
--page-bg: #f5f3ee;
--surface: #fbfaf7;
--text-primary: #24221f;
--text-secondary: #716d66;
--hairline: #dedad2;
--accent: #7b3f32;
```

以上颜色仅为方向示例。重点是减少纯黑纯白的强烈反差，以及避免用多种品牌色标记普通内容。

## 11. 正文宽度与排版参数

### 11.1 正文宽度

- 中文正文建议每行约 30–42 个汉字；
- 内容列最大宽度建议 `680–760 px`；
- 宽屏设备不应随视口无限拉宽正文；
- 打开原刊浮层时，可将正文收窄至 `620–700 px`，但不改变字号。

### 11.2 字号与行高

桌面端建议起点：

| 元素 | 建议字号 | 建议行高 |
|---|---:|---:|
| 正文 | 17–19 px | 1.75–1.95 |
| 导语 | 19–22 px | 1.65–1.8 |
| 一级标题 | 36–48 px | 1.15–1.3 |
| 二级标题 | 24–30 px | 1.3–1.45 |
| 辅助语言 | 主文的 85%–90% | 1.65–1.8 |
| 图片说明 / 元信息 | 13–14 px | 1.5–1.65 |

实际值需要结合中文、日文字体进行真机测试，尤其关注假名、Ruby、粗体和标点挤压。

### 11.3 字体建议

- 中文正文：优先选择可读性稳定的宋体或现代衬线体，也可使用成熟的黑体作为无衬线方案；
- 日文正文：选择覆盖完整、假名均衡的明朝体或 Gothic 字体；
- UI 控件：使用清晰的无衬线字体；
- 一篇文章内不宜同时使用过多字体；
- 字体加载失败时应有覆盖中日字符的可靠回退栈。

### 11.4 可调阅读设置

`Aa` 菜单可包含：

- 字号：小 / 标准 / 大；
- 行距：紧凑 / 标准 / 宽松；
- 主语言：中文 / 日本語；
- 辅助语言：关闭 / 点击显示 / 始终显示；
- Ruby：显示 / 隐藏；
- 主题：浅色 / 深色 / 跟随系统。

这些设置不应占据顶部主导航的多个按钮。

## 12. 桌面端最终布局草图

### 12.1 默认阅读状态

```text
┌──────────────────────────────────────────────────────────────────────────┐
```

## 13. 优先实施的 5 项改动

以下顺序以“最小结构变更获得最大阅读改善”为原则。

### P0-1：将阅读模式设为默认入口

- 一级入口调整为“阅读 / 对照 / 原刊 / 研究”；
- 中文或用户上次选择的语言作为主语言；
- 原有高信息密度页面暂时整体归入研究模式。

**预期收益：** 无需先重构全部数据，即可立即区分普通阅读与专业研究任务。

### P0-2：取消阅读模式中的 Region 卡片边界

- 按语义顺序串联 Region；
- 移除卡片背景、边框、编号和重复标签；
- 合并由 OCR 版面造成、但语义上连续的段落。

**预期收益：** 从根本上消除“逐条查看数据库记录”的感觉。

### P0-3：改为“主语言正文 + 按需辅助语言”

- 阅读模式只固定展示一种主语言；
- 在段落旁提供低存在感的“原文 / 译文”入口；
- 保留完整双栏能力到对照模式。

**预期收益：** 显著减少横向扫视和语言切换造成的打断。

### P1-4：将原刊改为缩略入口与侧边浮层

- 移除阅读模式中固定占据半屏的扫描页；
- 增加页码入口、缩略图和段落定位；
- 浮层内支持缩放及当前选区高亮。

**预期收益：** 保留原刊上下文与核验能力，同时让正文成为视觉主角。

### P1-5：默认隐藏 Entity、OCR、校对和 Region 技术信息

- 阅读模式彻底隐藏技术元信息；
- 对照模式仅显示与当前核对直接相关的异常提示；
- 完整信息集中到研究模式。

**预期收益：** 快速降低 Dashboard 感和认知负担。

## 14. 保留当前页面作为研究模式的迁移方案

### 14.1 迁移原则

不重写或删除当前页面，而是重新定义其产品角色：

> 当前页面不是失败的阅读界面，而是一套信息完整的研究工作台。

通过模式重命名和默认入口调整，可以先完成产品分层，再逐步优化各模式内部体验。

### 14.2 分阶段路线

#### 阶段一：模式分流

- 新增轻量阅读路由或视图；
- 当前页面迁移为研究模式；
- 共享同一套文章、页面、Region 和翻译数据；
- 模式切换保留文章 ID、页码与当前 Region 锚点。

#### 阶段二：连续内容渲染

- 增加内容角色与阅读顺序映射；
- 清理 OCR 硬换行；
- 合并语义连续的 Region；
- 建立标题、导语、采访问答、正文与图片说明组件。

#### 阶段三：上下文联动

- 实现段落与原刊坐标的双向定位；
- 增加原刊侧边浮层；
- 实现主语言与辅助语言的段落级切换；
- 模式切换时保持阅读位置。

#### 阶段四：研究模式精简与增强

- 对现有工具按任务重新分组；
- 将不常用字段折叠到详情区；
- 增加 OCR 异常、未校对和缺失映射等筛选；
- 保持研究模式高密度，但提高可操作性。

### 14.3 共享状态建议

四种模式之间应共享以下状态：

```ts
type ReaderContext = {
  articleId: string;
  pageId?: string;
  regionId?: string;
  paragraphId?: string;
  scrollAnchor?: string;
  primaryLanguage: "zh" | "ja";
};
```

这样用户可从阅读模式某一段进入研究模式检查 OCR，再返回同一阅读位置，而不是重新寻找上下文。

### 14.4 兼容现有数据的展示层

可以先新增一个非破坏性的适配层：

```text
现有 Region 数据
       ↓
阅读内容适配器
  - 排序
  - 合并
  - 角色识别
  - 硬换行清理
       ↓
连续文章节点
```

短期可用人工配置补充自动判断；长期再将内容角色与语义关系写入内容管理工具。这样能避免为了上线阅读模式而先进行高风险的数据迁移。

## 15. 验收清单

### 阅读体验

- [ ] 首次进入文章默认打开阅读模式；
- [ ] 首屏的视觉焦点是文章标题与正文；
- [ ] 正文中不出现可见 Region 卡片或编号；
- [ ] 用户无需查看原刊也能连续理解全文；
- [ ] 采访问答的说话人与节奏清晰；
- [ ] 长文行宽、字号和行距适合持续阅读。

### 信息披露

- [ ] 辅助语言默认不与主语言长期并排；
- [ ] 原刊可在不丢失阅读位置的情况下打开和关闭；
- [ ] 点击段落可以定位对应原刊选区；
- [ ] Entity、OCR、校对和 Region 信息在研究模式中完整可用；
- [ ] 普通阅读界面不暴露内容生产管线。

### 模式与迁移

- [ ] 阅读、对照、原刊、研究四种模式职责明确；
- [ ] 当前高密度页面已作为研究模式保留；
- [ ] 模式切换能保持文章、页码或段落上下文；
- [ ] 主语言和排版设置可被记忆；
- [ ] 原有 Region 与坐标映射无需被破坏。

## 16. 结论

这次优化不应以“删掉资料功能”为目标，而应重新安排它们出现的层级与时机：

- 阅读模式负责让用户读下去；
- 对照模式负责比较语言；
- 原刊模式负责欣赏和查看版面；
- 研究模式负责承载结构化数据与专业工具。

最关键的产品判断是：

> 保留 Region 作为底层能力，但不再让 Region 决定默认阅读界面的形态。

当扫描原刊、辅助语言和技术元信息都从“永久占据界面”变为“需要时立即出现”，产品既不会失去资料深度，也能获得真正连贯的杂志阅读体验。

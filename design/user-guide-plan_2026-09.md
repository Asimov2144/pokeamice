## 0. 缘起

各个 pokeamice 站点（文档站、App、Tour、Event）都在加功能、变复杂，读者不看代码就很难知道“这个站能干什么、该怎么用”。
用户的要求（2026-09-29）：

- 在文档站里加一批**说明文档**，先新建一个专题，把**文档站本身的使用方法**图文讲清楚；
- 形式照**游戏的功能介绍页**：要有**流程图、解说图、实机内容**；
- 专题名定为「使用指南」，以后其他站点的说明也放进来。

## 2. 和站点现有结构怎么接

读源码得到的约束（写之前先记下，避免做完才发现挂不上）：

- **导航顶层固定四项**（POsts · KEy docs · MOre at · News → PO KE MO N），`_data/navigation.yml` 的注释写明“新东西只能放在 children 里，不能加第五项”。所以「使用指南」挂在 **KEy docs 的 children**，不是新顶级项。同一份注释还要求“每个入口都指向真实存在的页面”，所以**没有第一篇之前不挂**。
- **首页专题图块**在 `_includes/home-topics.html`，每块 = 一张 `assets/img/topics/*.jpg`（336×192，由 `tools/build-topic-tiles.py` 的 TILES 生成）+ 类型词 + 标题 + 数字。制作名单、员工博客分析的类型词是「专题」，本专题沿用「专题」还是另叫「指南」见 §8。
- **面包屑**（`_includes/crumbs.html`）按 layout 而不是 URL 定路径；`library` 布局没有专属分支时只出「首页 › 本页」，不会出死链。若要出「首页 › 使用指南 › 本篇」，要给 crumbs 加一个分支（P2）。
- 页面布局：`library`（无侧栏，整个 #main，`/keys/` 用的就是它）适合专题首页；文章页需要放大图、编号圈、流程图，预计要一个专用布局 `guide`（见 §6），共用 library 的头部样式。
- 首页专题架在 `catalogue-seed` / 检索里**不是**文章条目，专题页（`_pages/`）默认 `search: false`；使用指南要不要进站内搜索，见 §8。

## 3. 篇目结构

**第一篇：《文档站怎么用》**，一页长文，页内锚点分节；写到超过 ~8 节再拆成分页（§8-1）。

开头一张**总览图**（一屏内标出站点的几个“入口”和它们的关系），然后一个功能一节，每节固定三段：

## 4. 图

### 流程图（内嵌 SVG，随站点深浅色）

- **A. 找资料的路径**：首页（搜索条 / 图块 / 维度）→ 检索结果 → 文章；旁支：分类与标签登记簿、`/keys/` 动态流 → 文章。
- **B. 一篇扫描帖怎么读**：进帖 → 舞台翻页 ⇄ 文字栏滚动（互相跟随）→ 悬停段落点亮页上热区 ⇄ 点热区回到段落 → 整页 / 缩放。
- **C. 一篇文章怎么串到别处**：文章 →「本篇提到」/ 人物名 / 面包屑 → 人物卡（悬停）→ 人物库 / 制作名单 / 时间线。

做法：手写 SVG 放在 `_includes/guide/`（`guide-flow-a.svg` 这类），页面里 `{% include %}`，颜色用 CSS 变量，不用图片文件——这样文字可被搜索、可跟随主题、改一个字不用重画。

### 解说图（截图 + 编号圈）

**不把编号烙进截图。** 截图只放干净的一张，编号圈用 HTML 叠在图上（位置写百分比），旁边的解说是同一份数据渲染出来的。好处：文案改了不用重拍，编号和解说不会错位，手机上可以把解说挪到图下面。

### 总览图

一张示意图（不是截图）：站点各入口和它们的关系，是 A / B / C 的“缩小合并版”，放在文章最顶上。

## 5. 实机截图

- 来源：**线上站点**（docs.pokeamice.com），不用本地 `_site`（本地快照会过期）。
- 宽度：桌面 1280，手机 390×844（工具 `tools/cdpshot.mjs`，CDP 走手机视口；内置浏览器 resize 后截图只剩左上四分之一，别用）。
- 格式与体积：WebP，单张 ≤ 250 KB，桌面图 2 倍宽（2560）不必要，1600 够用；放 `assets/img/guide/`。
- 例子要**稳定且有代表性**：用一篇不会被改的老帖当例子，不挑正在修订的帖。扫描阅读器要挑**已有热区的那两套试点**（先查是哪两套，不确定不写）。
- 每张图记：拍摄日期、页面 URL、视口。放进 `_data/guides.yml` 的 `shots`（§7），功能改了可以按“哪些图涉及哪个页面”反查。
- 不涉及个人信息（站点没有登录），不需要打码；截到第三方图片（杂志扫描）时按站内已有做法，不额外放大到能通读原文。

## 8. 待拍板

带推荐，直接回“按推荐”即可。

1. **第一篇一页长文还是分页？** 推荐**一页长文**：锚点足够，读者不用来回跳；超过 8 节再拆。
2. **图块类型词**：首页图块上写「专题」（与制作名单、员工博客分析一致）还是「指南」？推荐**「指南」**，让读者一眼分出“这是说明书，不是资料”。
3. **进不进站内搜索**：推荐**进**（`search: true`），搜“怎么用 / 扫描 / 对照”时能直接找到；代价是检索结果里混入一条非资料条目，需要在卡片上标类型。
4. **要不要专用布局 `guide`**：推荐**要**，library 太素，编号圈和节目录都得自己长在页里。
5. **URL**：`/guide/`（推荐）还是 `/help/`。
6. **App 资料室要不要带这篇**：默认不进（导出器只吃帖子）；要进的话需要另开一份导出，先不做。
7. **英文名 / 眉题**：现在写的是 “Guide · 专题”，可改。

## 二、全站排查：`tools/audit-translation-inflation.py`

```
python tools/audit-translation-inflation.py              # 排名
python tools/audit-translation-inflation.py --only <stem>  # 看某一篇被标的行
python tools/audit-translation-inflation.py --json <path>  # 明细
```

每一行判两件事：

- **long**：中文字数相对原文明显偏多。基准是全站同一文字的中位数比值，按每一段原文自己的文字判断（有假名 = 日文 0.755，拉丁字母 = 0.374），不看 `original_lang`，因为有 60 篇没填这个字段。条件是比值达到中位数的 1.6 倍、至少多出 25 字、原文至少 20 字。
- **phrase**：译文里出现渲染词（近乎变态、大铁闸、断舍离、堪称、简直、神来之笔、骨子里、登峰造极……共 60 个），而原文里没有能支撑它的词。例如「简直」要有まるで / 本当に / literally 才算有依据，「断舍离」要原文有「断捨離」才算。强词（weight 2）是忠实的访谈翻译几乎用不到的词；弱词（weight 1）是常用词，只有在原文找不到依据时才可疑。

只读不改。名字、图片路径、链接这类与原文相同的行跳过。

**校准。** 改之前，05-01 这一篇得 44.9 分（5 行偏长、15 个强词、18 个弱词），在全站第 22、首藤刚志回忆录以外排第 1。它的孪生篇 05-02 一行都没被标。

## 三、局限

- 长度比只说明「多」，不说明「错」。译注、补全的专有名词、日文省略主语之后中文补出的成分都会让句子变长。被标的行要人读过才能下结论。
- 渲染词表是手写的封闭表，所以只能抓到见过的套路。新的渲染写法要补进 `PHRASES`。依据词表也会漏，比如原文用了表里没收的强调词，就会冤枉一条。
- 原文栏本身是编出来的时候（像 05-01），长度比反而可能正常，因为编的日文和渲染的中文是一起写出来的。这种帖子要靠来源核对去抓，检测器只能顺带把它们排到前面。

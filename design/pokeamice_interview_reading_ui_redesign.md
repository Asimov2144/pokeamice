# PokeAmice Docs 访谈页面阅读体验改版建议

> 适用对象：PokeAmice Docs 中的访谈归档、翻译与年代化阅读页面  
> 核心目标：从“档案展示页”转向“可沉浸阅读的访谈页面”  
> 设计原则：**阅读 → 发现 → 档案**

---

## 1. 当前页面的核心问题

目前访谈页面的问题并不只是字体、配色或复古风格不足，而是更底层的：

- 信息架构偏“档案数据库”
- 正文进入过慢
- UI 控件数量过多
- 信息看似很多，但正文占屏比低
- 注释系统打断阅读
- 原文与译文的并列关系过强
- 访谈问答没有形成清晰阅读节奏
- 页面缺少“为什么值得读下去”的内容引导

因此会出现一个明显矛盾：

> 页面元素很多，但读者仍觉得“信息密度不高”。

本质上是：

> **视觉密度低，UI chrome 密度高。**

---

# 2. 重新定义页面的第一目标

当前页面更接近：

> 档案 → 工具 → 阅读

建议改成：

> **阅读 → 发现 → 档案**

用户第一次打开页面时，最重要的任务应该是：

1. 迅速理解这是谁、什么时候、在哪里接受了什么采访
2. 知道这篇访谈为什么值得读
3. 尽快进入正文
4. 阅读过程中自然发现人物、作品、地点、背景知识
5. 需要研究时，再主动进入档案层

---

# 3. 正文进入得太慢

## 当前问题

标题之后通常还有多层内容：

- 基本资料卡
- Archive Record
- 阅读模式
- 氛围模式
- 专注模式
- Archive Route
- 访谈阵容
- 逐段译读

真正正文出现得太晚。

并且日期、来源、人物、语言、状态等信息会重复出现。

---

## 建议

正文最好在标题后约 **300–500px 内出现**。

首屏结构建议压缩为：

```text
POKE AMICE / ARCHIVE / 1999

TIME · NOV 22, 1999

究极的 Game Freak
田尻智专访

1999年，在《宝可梦》席卷美国之际，
TIME 采访了刚刚完成《金／银》的田尻智。

田尻智 × TIME
约 18 分钟阅读

[ 开始阅读 ]

昆虫少年   Game Freak   通信线   梦幻   宫本茂
```

然后立即进入正文。

---

# 4. 顶部元信息应该压缩

默认只保留一行：

```text
TIME · 1999.11.22 · 田尻智 · 英文原文 · Poke Amice 译
```

详细档案信息全部收入：

```text
ⓘ 档案信息
```

点击后展开：

- Source
- Date
- Original URL
- Language
- Translation status
- OCR status
- Proofreading status
- Archive source
- Capture date
- Version note
- Encoding note

---

## 原则

**Archive Record 不属于默认阅读流。**

它应该是研究功能，而不是正文前置内容。

---

# 5. 注释系统需要大幅减法

## 当前问题

大量注释属于：

- 常识解释
- OCR 错误解释
- 人名基础说明
- Game Boy / Game Freak 等基础名词说明
- 同一种乱码反复解释

这些内容对资料研究有价值，但对连续阅读形成明显阻力。

---

# 6. 注释建议拆成三层

| 类型 | 例子 | 默认显示方式 |
|---|---|---|
| 阅读必需 | 原文日期与实际发售日不符 | `※` 或小型脚注 |
| 延伸知识 | Quinty、Space Invaders、人物、作品 | Entity Link / Tooltip |
| 档案校勘 | OCR乱码、编码异常、拼写错误 | 仅档案模式显示 |

---

## 6.1 阅读必需注释

例如：

```text
《宝可梦 金／银》将于11月20日在日本发售。※
```

点击：

```text
※ 原文如此。《宝可梦 金／银》实际于 1999 年 11 月 21 日发售，
可能是原报道笔误。
```

这种注释：

- 会影响理解
- 有历史价值
- 值得保留

---

## 6.2 延伸知识改成 Entity

例如：

```text
Game Boy
Game Freak
Quinty
Space Invaders
宫本茂
梦幻
```

不再全部显示成：

```text
[注]
```

而是直接变成可点击实体。

点击 Game Boy：

```text
Game Boy
Nintendo · 1989

掌上游戏机。

Related:
Pokémon
通信线
田尻智
```

这样注释系统可以逐渐转化成 PokeAmice 的知识图谱。

---

## 6.3 档案校勘完全退出阅读模式

例如：

```text
Pok駑on → Pokémon
```

不应该每次正文出现都产生一个注释。

应该在 ingest / OCR normalization 阶段统一修复。

档案模式只记录一次：

```text
原始网页存在字符编码错误，
本文已统一将 Pok駑on 修复为 Pokémon。
```

---

# 7. “注”按钮本身也建议移除

当前单独的：

```text
[ 注 ]
```

很像：

- 编辑器
- CMS 控件
- 文档审阅工具

不属于自然阅读语言。

建议替换为：

```text
※
¹
ⓘ
```

或者完全不显示按钮。

---

# 8. 访谈必须恢复“对话节奏”

当前结构如果类似：

```text
6 时代周刊

原
原文
...

译文
...

田
田尻智
受访

7 田尻智

原
原文
...
译文
...
```

这是一种非常明显的数据库记录结构。

对阅读来说，应该重新恢复：

> 提问 → 回答 → 提问 → 回答

---

# 9. 推荐的默认访谈样式

```text
TIME

你还好吗？你看起来很累。

田尻智

这就是我的工作方式。
我睡12个小时，然后工作24个小时。
过去三年我一直这样不规律地工作。
为了想出点子，最好日夜颠倒。
我通常靠这种作息来获得游戏设计的灵感。


TIME

你是如何开始设计游戏的？

田尻智

我是看着漫画和动画长大的第一代人。
那是在《哥斯拉》之后。
我非常沉迷《奥特曼》……
```

也可以进一步简化成：

```text
Q

你是如何开始设计游戏的？

田尻智

我是看着漫画和动画长大的第一代人……
```

---

# 10. 删除大量结构标签

默认阅读模式中应尽量去除：

```text
原
原文
译文
受访
提问
6
7
8
```

这些信息不是内容，而是数据结构。

---

# 11. “译文优先”应该真正成为主模式

目前即使提供：

```text
译文优先
左右对照
纯原文
```

如果底层正文仍然同时渲染原文与译文，那么视觉上依然是一个 Parallel Reading Reader。

建议重新定义。

---

# 12. 阅读模式

默认：

```text
只显示中文
```

原文入口放在段落边缘：

```text
EN
```

点击当前段落的 `EN`：

```text
[中文译文]

—— English

[当前段落原文]
```

只展开当前段落。

---

# 13. 研究模式

主动开启后才显示：

```text
中文 | English
```

左右对照。

此时可以出现：

- 注释编号
- 原文行号
- OCR 差异
- Archive Record
- Source Link
- Revision info

---

# 14. 页面功能优先级

应该明确：

> **阅读是一等公民。**

> 对照、校勘、档案是工具。

而不是：

> 对照系统是一等公民，“译文优先”只是一个显示状态。

---

# 15. 页面需要“内容引导”，但不要增加长导读

不建议在标题与正文之间增加 300–500 字背景介绍。

那会进一步延迟正文。

建议只保留一句：

```text
1999年，《时代》在《宝可梦 金／银》发售前后采访了田尻智。
从昆虫少年、Game Freak 同人志，到 Game Boy 通信线、
梦幻与宫本茂，他回顾了宝可梦诞生背后的许多核心想法。
```

---

# 16. 增加主题导航，而不是 UI 功能导航

例如：

```text
昆虫少年
Game Freak
通信线与宝可梦
梦幻
宫本茂
```

这些导航告诉用户：

> 这篇文章有什么值得看。

而不是：

```text
阅读模式
专注模式
氛围模式
档案模式
```

后者只是在告诉用户：

> 这个页面有什么功能。

---

# 17. 两种导航需要分层

## 第一层：内容导航

默认可见：

```text

梦幻

```

## 第二层：工具导航

收进右上角：

```text

```

展开：

```text

档案信息

```

---

# 18. 年代感不要依赖“控制面板”

PokeAmice 的 1996–2026 年代化页面设计应该来自：

- 字体
- 链接样式
- 分隔线
- 小型像素图标
- 页面宽度
- 导航设计
- 背景纹理
- 图片处理
- 引用样式
- 页脚结构

而不是通过大量：

```text
Retro Mode
Archive Mode
Atmosphere
Focus
Theme
```

来告诉用户：

> 这是一个复古页面。

---

# 19. 1999 页面建议的视觉语言

可以使用：

- 较窄正文宽度
- 低饱和背景
- 轻微网页纸张感
- 蓝色超链接
- 小字号 metadata
- 水平分隔线
- 简单 serif / sans 混排
- 局部像素元素
- TIME 风格的编辑排版感
- 很少的圆角卡片

避免：

- 大量 dashboard card
- 大量 pill
- 大量按钮
- 每段都出现 badge
- 现代 SaaS 控制台风格

# 22. UI 层级建议

页面只保留三个层级。

## Level 1：正文

永远最突出：

- Question
- Answer
- 图片
- 章节

## Level 2：发现

次级：

- Person
- Pokémon
- Game
- Place
- Timeline
- Related interview

## Level 3：档案

最弱：

- OCR
- Archive source
- Metadata
- Encoding
- Revision
- Original HTML

---

# 23. 第一阶段：只做减法

暂时不要继续增加新功能。

优先完成：

- [ ] 删除默认显示的 Archive Record
- [ ] 删除正文中的「原 / 原文 / 译文」标签
- [ ] 默认只显示译文
- [ ] 将 70–80% 的注释退出阅读模式
- [ ] OCR / encoding note 移入 Archive
- [ ] 将标题到正文距离压缩至 300–500px
- [ ] 恢复 Q → A 的访谈阅读结构
- [ ] 删除正文 record number
- [ ] 降低 badge / pill / card 数量

---

# 24. 第二阶段：建立内容引导

完成：

- [ ] One-line intro
- [ ] Reading time
- [ ] 章节主题导航
- [ ] 阅读进度
- [ ] Section anchor
- [ ] 下一章节提示

---

# 25. 第三阶段：Entity 化

将目前大量注释改造成：

```text
Person Entity
Pokémon Entity
Game Entity
Hardware Entity
Place Entity
Event Entity
```

支持：

```text
hover
click
side panel
related content
timeline
```

---

# 26. 第四阶段：建立真正的 Archive Mode

Archive Mode 再显示：

- 原文
- 翻译
- OCR
- 校勘
- Source
- Snapshot
- Version history
- Encoding fix
- 原始 HTML
- 图片来源
- 页码
- 其他译本

这样档案能力不仅没有丢失，反而会更加专业。

---

# 27. 最重要的设计判断

不要把页面设计成：

> **1999 年档案页面**

更适合的方向是：

> **2026 年的人，在 PokeAmice 中阅读一篇 1999 年留下来的访谈。**

这意味着三层体验应该是：

### 第一层

**阅读**

让用户忘记 UI。

### 第二层

**发现**

让用户逐渐进入 Pokémon 历史网络。

### 第三层

**档案**

让研究型用户获得完整证据链。

---

# 28. 最终设计原则

```text
READ
↓
DISCOVER
↓
ARCHIVE
```

而不是：

```text
ARCHIVE
↓
TOOLS
↓
READ
```

---

# 29. 判断一次改版是否成功

可以用以下问题检查：

- 打开页面 5 秒内，能否知道这是谁的访谈？
- 半屏内能否看到第一段正文？
- 不点任何按钮，是否可以完整读完文章？
- 阅读时是否几乎感觉不到 CMS / 数据库结构？
- 原文是否只有用户主动需要时才出现？
- 注释是否真正帮助理解，而不是展示资料完整性？
- 页面是否告诉用户“这篇文章有什么值得读”？
- 访谈是否有明显 Q → A 节奏？
- 年代感是否来自阅读体验，而不是 Theme 按钮？
- 深度研究信息是否仍然可以在 Archive Mode 中完整获得？

如果大部分答案是“是”，说明页面已经从：

> 资料展示页面

转向：

> 数字档案驱动的阅读产品

---

## 一句话总结

> **PokeAmice 访谈页下一阶段最需要的不是继续加功能，而是通过大幅减法，让正文成为页面本身，再把年代感、实体网络和档案能力逐层叠加回去。**

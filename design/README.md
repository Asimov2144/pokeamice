# Pokémon Web Screenshot Reference Board

> **用途**：PokeAmice Docs / Interview / Scan Archive 的 Era Skin 视觉研究库。  
> **范围**：1999–2026，官方门户、游戏专题站、Daisuki Club、PGL、Pokémon Center、社区资料站/论坛等。  
> **原则**：这些截图用于**设计研究与结构提炼**，不是建议逐像素复刻，也不建议将第三方/受版权保护截图直接作为公开站点素材重新发布。

---

## 怎么使用这个 Board

每篇访谈不要从一个旧网站“整套抄皮肤”，而是同时选三种参考：

1. **Era Structure**：这个年代的网站骨架应该是什么感觉；
2. **Source Accent**：原始资料是杂志、报纸、博客、官方网站还是书；
3. **Pokémon Context**：作品、人物、地区或活动只提供局部色彩/图像线索。

例如：

```text
2008 Nintendo DREAM 访谈
= 2006–09 DS Web 的圆角/栏目节奏
+ Magazine 的 VOL / PAGE / CAPTION
+ Platinum 的少量作品 accent
```

而不是：

```text
2008 = 整页做成 Nintendo DS UI
```

### 核心筛选标准

- **CORE**：直接影响 Era Skin / Docs 信息架构，优先做成组件；
- **SECONDARY**：适合提取某一种布局、交互或媒介语法；
- **CONTRAST**：用于理解“同年代但不同站点身份”的差异，避免把 Pokémon Web 简化成一种官方风格。

## Priority Map

### CORE
- Pokémon World 1999 — Early Web 的目录/门户逻辑
- Pokémon.com 2002 — 品牌门户与内容格
- Serebii.net 2003 — 社区资料高密度
- Daisuki Club 2004/2005 — 场景式探索与角色引导
- Bulbapedia 2006 — 知识库/研究模式
- Pokémon.com 2010 — Web 2.0 模块化
- PGL 2011 — Connected Service / Dashboard
- Daisuki Club 2012 — Editorial Media 转折
- Sword / Shield 2019 — 世界观主导的现代 microsite
- Pokémon Official 2026 — PokeAmice 现代层的终点参考

## Reference Cards

### 1999 · Pokémon World  `CORE`


> 截图请打开来源页查看（该档案图库当前未提供稳定的可直接嵌入图片 URL）。

**类型**：Official portal  
**Era**：01 Early Web  
**参考标签**：`portal` · `3-column` · `index` · `pokedex` · `pattern`

| 观察项 | 记录 |
|---|---|
| Layout | 固定窄幅三栏：左侧目录 / 中央新闻 / 右侧 Pokédex |
| Navigation | 大量常驻文本按钮，目录本身就是站点地图 |
| Visual | 高饱和黄、重复纹理、1px 边框、链接蓝、小型角色插图 |
| Pokémon usage | Pikachu、Charizard、Pokédex 直接承担导航与栏目识别 |
| PokeAmice 可复用 | Era Masthead、旧网页式 Index、1px divider、source metadata、小型 NEW 标识 |
| 不建议照搬 | 不要复制小字号、重复背景覆盖正文、过量 GIF/闪烁效果 |

**一句话结论**：早期 Pokémon Web 的关键不是像素，而是“网页是一座可以探索的目录”。

**截图 / 来源**：[archival gallery](https://www.webdesignmuseum.org/gallery/pokemon-world-in-1999)

### 2003 · Serebii.net  `CORE`


![Serebii.net — 2003](https://johtotimes.com/web/images/serebiinets-layout-from-december-2003.png)

**类型**：Community news / database  
**Era**：02 Portal / GBA  
**参考标签**：`community` · `dense` · `news` · `sidebar`

| 观察项 | 记录 |
|---|---|
| Layout | 三栏高密度信息页：左侧巨大目录，中间更新流，右侧最近内容 |

| Pokémon usage | Celebi 是站点身份，内容本身比品牌装饰更重要 |

| 不建议照搬 | 不要把这种密度搬进访谈正文 |

**一句话结论**：社区站的价值在“稳定、高密度、每天都能回来找东西”，不是现代品牌感。

# 对 PokeAmice 最重要的 8 个可复用 Pattern

## Pattern A — Archive Index
来源：Pokémon World 1999 + Serebii 2003 + Bulbapedia 2006

适合：

- Docs 首页
- 人物索引
- 游戏索引
- 杂志索引
- 年表

不适合：

- 访谈正文

---

## Pattern B — Scene Navigation
来源：Daisuki Club 2004 / Summer Challenge 2005

在 PokeAmice 中应缩小为：

- “原刊”
- “相关人物”
- “同作品访谈”
- “下一份档案”
- “回到当年”

这些入口可以带一点路牌 / discovery 的味道，但不要做成小游戏。

---

## Pattern C — Archive Record
来源：PGL 2011 / 2016

只用在正文外层：

```text
DATE
SOURCE
PEOPLE
GAME
PAGE
LANGUAGE
STATUS
```

这部分可以有 2010s Dashboard 的结构，但正文必须保持阅读模式。

---

## Pattern D — Source Shelf
来源：Pokémon Center 2008

把：

- 杂志封面
- 扫描页
- 书籍
- 同期资料

当作“可收藏的实体”陈列。

---

## Pattern E — Editorial Lead
来源：Daisuki 2012 / Slowpoke 2014

允许一张扫描图、封面或人物照片成为文章开头的视觉锚点。

---

## Pattern F — Region / Work Atmosphere
来源：Sword / Shield 2019

对现代访谈可以让作品世界观进入 Hero / Chapter Lead，但控制在正文之外。

---

## Pattern G — Community Density
来源：Serebii / Bulbapedia / PokéBeach

“资料很多”不是问题，问题是资料密度必须放在：

- Index
- Sidebar
- Footer
- Related
- Search

而不是正文。

---

## Pattern H — Modern Quietness
来源：2026 Pokémon Official

2022–2026 页面无需再用大量 Poké Ball、像素、扫描线证明“怀旧”。

PokeAmice 的 Pokémon 感应该越来越来自：

- Entity
- Timeline
- Place
- Person
- Game
- Scan
- Cross-link

# 设计时的三问

每次要从 Board 取灵感时，只问：

1. **这个旧页面最有价值的是“结构”、 “装饰”，还是“交互逻辑”？**
2. **这一点放进长篇阅读，会增强资料的年代感，还是只会打断阅读？**
3. **即使把 Pokémon 图片全部拿掉，这个设计理念还成立吗？**

如果第三问答案是“完全不成立”，通常说明我们复制的是表面皮肤，不是设计语言。

# 截图版权与使用边界

本 Board 中很多图片是：

- 官方网站的历史截图；
- Bulbagarden Archives 等处基于 fair use 保存的截图；
- Web Design Museum 的历史网页展示；
- 社区站自有历史截图；
- 新闻/博客中转载的旧官网截图。

**建议用途：内部设计研究、对比分析、开发参考。**

上线 PokeAmice 时，优先：

1. 自己在 Internet Archive / 官方现存页做研究；
2. 只提炼 CSS/布局语言；
3. 不把这些第三方截图直接作为网站装饰素材；
4. 若文章本身需要展示“历史网站长什么样”，再单独记录来源与合理使用依据。


建议下一轮直接制作：

**`PokeAmice Era Skin Token Spec`**

把这里每个视觉判断变成可以写进 SCSS 的变量，例如：

```yaml
early_web:
  page_width: 820px
  reading_width: 740px
  radius: 0px
  border: 1px
  shadow: none
  link_style: classic
  divider: hard
  metadata_style: table

ds_web:
  radius: 6px
  divider: dotted
  badge: sticker
  source_panel: soft
```

这样 Board 就不会停留在 moodboard，而会直接进入实现层。
